# Configured-pay fixture contract v1

[Shared contracts](../README.md)

`configured-pay-v1.json` contains fourteen synthetic cases with independently calculated arithmetic.
It is the first shared native-client conformance subset, **not** the complete iOS regression suite,
a statutory-pay audit, a verified agreement pack or evidence that Android/PWA clients work.

The existing native engine consumes every case through `SharedPayrollContractTests`. Future clients
must calculate the same amounts, preserve the named work facts and separate allowances/guarantees
without copying an implementation or modifying expected values to fit a new engine.

## Explicit inputs

- Decimal rates, multipliers, thresholds and expected money are strings with `.` as separator.
  Parse exactly; binary floating-point money arithmetic is prohibited.
- Currency is explicit; no exchange-rate conversion is implied.
- Each work interval and break has a synthetic UUID and UTC start/end instant. `timeZone` is the
  payroll IANA context used for local work dates, midnight and daylight-saving behavior.
- A physical callout has its own `calloutEventID`. Adjacent segments share that ID only when the
  fixture explicitly states they are the same event. Guarantees never create worked time.
- Every agreement has an immutable ID/version and explicit optional-rule settings. An empty array
  or null means that configured rule is absent; it does not waive an unassessed legal obligation.
- `premiumCombination` is `highestApplicable`. Multipliers are not silently compounded.
- Rounding specifies scale, mode and aggregation scope. Per-diem amounts remain separate from wages.
- v1 has empty regular-schedule/date-premium arrays. Adding nonempty cases requires deliberate
  consumer support; they may not be silently ignored.

## Expected output and provenance

Each case gives wages, allowances, actual-work and guarantee category sums, worked seconds, applied
multipliers, local work dates, and the expected rule-snapshot ID/version. The arithmetic note is an
independent worked explanation, not output generated by a calculator. Runtime explanation text can
be localized, but applied references and nonempty explanations must remain traceable to work/rules.
Component IDs can be client-local; source work and snapshot identities must be preserved.

Cases cover straight time, daily tiers, explicit double time, unpaid breaks, local-midnight reset,
DST spring/fall elapsed time, isolated and split physical callout minima, separate events, separate
per diem, highest-premium precedence, fractional-hour cent rounding and currency context.

Weekly regular-rate obligations, jurisdiction/applicability, effective-dated interactions, source
rights/review, negative/refusal cases and benefits are **not covered by this first subset**. Porting
these fourteen examples alone is insufficient to claim full parity or legal completeness. Existing
native coverage and source/applicability boundaries remain binding.

```bash
bash scripts/agent-verify.sh quick
```

That command verifies the shared cases with the existing pure native engine and the wider domain
suite. It does not build or run an Android/PWA client. A change to fixture meaning must be reviewed
as a contract version change; preserve historical expected arithmetic and explain the change.
