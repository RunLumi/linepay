Production verification used normal public DNS/HTTPS and fresh synthetic browser contexts.
All32runtime assets matched the built bytes; MIME/security/cache headers,11private/missing-path
refusals and POST405 passed. Chromium and WebKit, through Playwright1.55.0, completed configured
pay → confirmed comparison → reviewed Blob report/download/print → encrypted backup → reload
with retained local records. Browser HTML matched the reviewed bytes, and requests were only
same-origin GETs. Hosted browser, documentation and legal checks passed for the merged source.

The first production version, `c8159e8a-59b6-4f74-950c-18f070d65a11`, passed plain HTTP/WebKit
checks but failed Chromium's network check because the zone injected Cloudflare Web Analytics.
PR116 added documented `no-transform`, exact browser HTML checks and cachev13. The final browser
checks passed after redeployment. Do not reinterpret the first failure as a passing release.

The apex/www marketing Worker remains separate. No account, pay-data API, server database,
analytics collector or automatic backup was added. Ordinary CDN request metadata remains part
of hosting. Pay records stay in the browser unless deliberately exported. Current backups remain
web-format snapshots; native interchange and broader parity are not established by these checks.

The served weekly reference is still engine2. A prepared version3 correction addresses a
zero-basis residual-cent allocation and stricter work-duration admission. That separate reference
does not enter configured cash or clear missing paycheck mapping. This publication receipt does
not certify every payroll case; follow the [execution ledger](../../plan/v2-execution.md).
